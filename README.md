# Free Mine Public Server

Сервер обеспечивает работу:
1. Клиентского веб-приложения Free Mine;
2. Локального сервера владельца системы.

Доменная модель описана в репозитории https://github.com/free-mine/contracts.

## Функциональность

Смарт-контракты публикуют события в ходе своей работы. Сервер должен агрегировать эти события в текущее состояние, хранить его вместе с номер блока, для которого это состояние актуально и отдавать данные по запросу.

Периодически (например, каждый час) сервер запрашивает RPC-провайдер, обновляя текущее состояние и номер актуального блока.

Для локального сервера владельца системы публичный сервер служит надёжным хранилищем данных о текущем состоянии транзакций.

## Данные

Во-первых, агрегируются данные самих контрактов из системы Free Mine:
- Адреса и количество `MagicOre` держателей.
- Расписание вступления в должность преемников `OreVein`.
- Цены, заявки и прочие данные `FreeMine`.

Во-вторых, агрегируются данные размещения капитала на адресе `OreVein`. Наблюдаемые токены: WAVAX, BTC.b, USDT и USDC. Также, WAVAX и BTC.b в качестве вкладов в AAVE, а USDT и USDC в качестве долга в AAVE. Должно быть понятно, сколько чего вложено и сколько чего взято (без долларовых эквивалентов). Если из AAVE можно запросить Health Factor, то и его тоже.

Также в размещение капитала входят торговые пары в Uniswap V3 (с полным или ограниченным диапазоном):
- WAVAX/USDC 0.05%.
- BTC.b/USDC 0.05%.
Должно быть понятно, какие торговые пары созданы и какой в них диапазон. Диапазон должен быть не в виде тиков, а в виде стоимости волатильного актива в USDC. Также надо агрегировать и текущую стоимость волатильного актива в USDC для каждой торговой пары.

Код должен быть написан таким образом, чтобы не было проблемой добавить поддерживаемые токены и торговые пары.

## Авторизация

Локальный сервер владельца системы отправляет секретный ключ при каждом запросе. Хеш этого ключа должен совпадать со значением, которое публичный сервер хранит локально в отдельном файле (чтобы я мог менять секретный ключ, просто обновив файл).

## Бэкапы

При агрегации данные контрактов из системы Free Mine вместе с номером последнего актуального блока должны сохраняться в файл. Желательно в оптимизированном виде. Этот файл доступен для скачивания кому угодно, потому что ничего секретного в нём нет, только данные из блокчейна. Я буду периодически скачивать этот файл в качестве бэкапа, чтобы при переустановке сервера не приходилось перебирать все блоки заново.

Соответственно, новый сервер должен иметь механизм чтения файла-бэкапа и применения данных из него.

## Технологии

Код сервера должен быть написан на TypeScript, а сам сервер должен запускаться командой `docker compose up -d`, то есть содержать в корне `compose.yml`, в котором будут описаны все зависимости сервера (например, СУБД, если нужна). Если зависимости не нужны серверу, то и хорошо, будет `compose.yml` с одним сервисом. Для RPC-провайдера используй EthersJs.

ESLint + Prettier должны быть настроены по предоставленной конфигурации.

## Запуск

Реализация использует Node.js 24, Ethers.js и Fastify. СУБД не требуется:
один процесс сохраняет данные в Docker volume `data`. Запускайте только один
экземпляр сервера для одного каталога данных.

1. Скопируйте `.env.example` в `.env` и задайте `RPC_URL` для Avalanche C-Chain
   (`43114`). Адреса существующих контрактов уже настроены.
2. Для запросов владельца создайте ключ командой `npm ci`, затем
   `npm run key:generate`. Команда выводит новый секретный ключ и сохраняет
   только его SHA-256 в `secrets/owner-key.sha256`.
3. Выполните `docker compose up -d`.

Вариант создания ключа без Node.js на хосте, после `docker compose build`:

```sh
docker compose run --rm --no-deps --user 0 --volume ./secrets:/app/secrets:rw server node dist/cli/key.js
```

Сохраните выведенный ключ на локальном сервере владельца. Авторизация:
`Authorization: Bearer <ключ>`. Файл хеша перечитывается при каждом запросе:
повторный запуск генератора немедленно заменяет действующий ключ. В контейнер
монтируется каталог `secrets`, поэтому атомарная замена файла видна без
перезапуска. Без корректного файла хеша публичные запросы работают, а запросы
владельца получают `401`. Доступ извне следует предоставлять через HTTPS.

По умолчанию HTTP доступен на порту `3000`. Для локальной разработки:
`npm ci`, `npm run dev`. Команды `dev` и `start` читают `.env`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `RPC_URL` | публичный RPC Avalanche | RPC с доступом к журналам с момента деплоя и состоянию выбранного блока |
| `PORT` | `3000` | Порт HTTP на хосте |
| `SYNC_INTERVAL_MS` | `3600000` | Интервал обновления |
| `LOG_BATCH_SIZE` | `2000` | Максимальный диапазон одного запроса событий |
| `RPC_TIMEOUT_MS` | `30000` | Таймаут RPC-запроса |
| `CHAIN_CONFIG_FILE` | встроенная конфигурация | JSON с контрактами, токенами и парами |
| `DATA_DIR` | `./data` | Каталог данных при запуске без Docker; в контейнере `/app/data` |
| `OWNER_KEY_HASH_FILE` | `./secrets/owner-key.sha256` | Файл хеша при запуске без Docker |

Публичный RPC имеет ограничения частоты. Первичная индексация читает события
от транзакции деплоя и может быть длительной; для постоянной эксплуатации
задайте собственный RPC. Последующие обновления начинают с блока после
сохранённого снимка. Пока первый снимок не готов, запросы данных возвращают
`503`, а хранилище транзакций владельца уже доступно.

## Данные и согласованность

Все публичные данные относятся к одному блоку. Сервер сохраняет номер, хеш и
время этого блока. События восстанавливают держателей `MagicOre`, активные
заявки, администраторов и расписание преемников. Остальные поля читаются через
геттеры контрактов с тем же `blockTag`. Расписание означает время, с которого
преемник может самостоятельно вызвать `claimPrivileges`; автоматического
получения полномочий нет.

История не сохраняется. У `FreeMine` остаются текущая и предыдущая смены,
а также более ранние смены, в которых ещё есть активные заявки. Балансы
держателей отражают реальные балансы ERC-20: заблокированные в заявках токены
находятся на `FreeMine`; связь с пользователями находится в `claims`.

Портфель содержит AVAX, наблюдаемые ERC-20, вклады и долги Aave с начисленными
процентами, Health Factor и непосредственно принадлежащие `OreVein` NFT
Uniswap V3. При отсутствии долга Health Factor равен `null`.

Суммы и идентификаторы контрактов — десятичные строки, суммы указаны в
минимальных единицах токена. `decimals` передаётся рядом с описанием токена.
Цена входа `FreeMine` имеет 18 знаков. В Uniswap `range.lowerPrice`,
`range.upperPrice` и `price` — обычные десятичные строки цены базового актива
в котируемом токене (USDC для настроенных пар); это не тики и не raw units.
`fullRange` обозначает полный допустимый диапазон пула. Расчёты выполняются
через `bigint`, без потери точности больших сумм в `Number`.

Для каждой позиции Uniswap:

- `amounts` — оба актива в действующей ликвидности, отдельно `base` и `quote`.
- `newlyAccruedFees` — комиссии, начисленные после последнего обновления
  учёта позиции, вычисленные по росту комиссий внутри диапазона.
- `storedOwed` — уже записанные контрактом суммы к получению.
- `totalCollectable` — `storedOwed + newlyAccruedFees`.

Сам Uniswap объединяет в `tokensOwed` ранее учтённые комиссии и капитал,
выведенный из ликвидности, но ещё не полученный через `collect`. Поэтому
`storedOwed` и `totalCollectable` не называются чистыми комиссиями: восстановить
такое разделение из текущего состояния нельзя. При нулевом `storedOwed`
`newlyAccruedFees` содержит все комиссии к получению.

Снимок публикуется только после успешного чтения всех данных и атомарного
сохранения файла. Ошибка RPC оставляет предыдущий снимок доступным. Запросы
обновления, поступившие одновременно, используют одну синхронизацию.
На Avalanche читается последний исполненный принятый блок; перед продолжением
проверяется хеш сохранённого блока. Несовпадение блокирует обновление и требует
проверки RPC или восстановления правильного бэкапа.

## HTTP API

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| `GET /health` | публичный | Процесс обслуживает HTTP |
| `GET /ready` | публичный | `200`, если есть снимок, иначе `503` |
| `GET /v1/status` | публичный | Состояние синхронизации, блок, время снимка и последняя ошибка |
| `GET /v1/state` | публичный | Полный снимок `{format, chain, block, updatedAt, fund, portfolio}` |
| `GET /v1/fund` | публичный | `{block, data}` с данными Free Mine, включая преемников |
| `GET /v1/portfolio` | публичный | `{block, data}` с портфелем |
| `GET /v1/backup` | публичный | Сжатый публичный снимок `free-mine-backup.json.gz` |
| `POST /v1/refresh` | владелец | `202`: обновление запущено или уже выполняется |
| `GET /v1/transactions` | владелец | `{records: [...]}` |
| `GET /v1/transactions/:id` | владелец | Запись и заголовок `ETag` с её ревизией |
| `PUT /v1/transactions/:id` | владелец | Создание или полная замена JSON-объекта |
| `DELETE /v1/transactions/:id` | владелец | Удаление записи, `204` |

Чтение публичных данных доступно браузерному приложению через CORS.
Неуспешное обновление не меняет номер блока. Клиент может оценивать свежесть
по `updatedAt` и смотреть ход обновления через `/v1/status`.

Хранилище транзакций не зависит от формата старого `admin-server`. Клиент
выбирает ID и JSON-объект записи (например, хеш, статус и данные для
восстановления операции). Сервер не подписывает, не отправляет и не проверяет
транзакции. ID: 1–128 символов из букв ASCII, цифр и `._:-`, первый символ —
буква или цифра. Максимальное тело HTTP-запроса — 1 MiB.

Создание записи:

```http
PUT /v1/transactions/operation-123
Authorization: Bearer <ключ>
If-None-Match: *
Content-Type: application/json

{"hash":"0x...","status":"submitted"}
```

Ответ `201` содержит `{id, revision, updatedAt, data}` и `ETag: "1"`
(фактическая ревизия может отличаться). Для замены или удаления передайте
`If-Match: "1"` с полученной ревизией. Без условия сервер возвращает `428`,
при конфликте — `412`: сначала прочитайте актуальную запись и согласуйте
изменения. Ревизии не переиспользуются после удаления. Ответ на изменение
возвращается только после записи на диск; одновременные записи сериализуются.
Журнал доступен только владельцу и отсутствует в публичном бэкапе.

## Бэкап и восстановление

В volume находятся два независимых файла:

- `public-snapshot.json.gz` — текущие публичные данные и позиция индексации.
- `transactions.json` — записи владельца.

Скачать бэкап можно без авторизации:

```sh
curl --fail http://localhost:3000/v1/backup --output backup.json.gz
```

Для восстановления на новом сервере с пустым volume:

```sh
docker compose build
docker compose run --rm --no-deps --volume ./backup.json.gz:/backup.json.gz:ro server node dist/cli/restore.js /backup.json.gz
docker compose up -d
```

Локальный вариант: `npm run backup:restore -- ./backup.json.gz`.
Останавливайте сервер перед восстановлением. Команда отказывается заменять
существующий снимок. Проверяются версия формата, сеть, адреса развёртывания,
структура и согласованность данных. При следующей синхронизации RPC должен
подтвердить хеш сохранённого блока. Используйте собственный доверенный бэкап:
один хеш блока не доказывает правильность произвольного JSON. Публичный бэкап
не восстанавливает журнал владельца.

## Добавление токенов и пар

Встроенная конфигурация находится в `src/config/constants.ts`. Полный JSON
можно получить командой `npm run --silent config:print` или из образа:

```sh
docker compose run --rm --no-deps server node dist/cli/config.js
```

Сохраните JSON в `config/chain.json`. Для Docker задайте
`CHAIN_CONFIG_FILE=/app/config/chain.json` в `.env`; для локального запуска —
`CHAIN_CONFIG_FILE=./config/chain.json`. В `tokens` задаются `symbol`, `address`,
`decimals` и необязательная роль Aave `supply` или `borrow`; в `pairs` —
`baseSymbol`, `quoteSymbol`, `fee` (500 соответствует 0,05%). Символы и адреса
токенов должны быть уникальны. После изменения конфигурации пересоздайте
контейнер командой `docker compose up -d --force-recreate`.

## Проверки и устройство кода

`npm run check` запускает проверку типов, ESLint, тесты и сборку. Тесты
не требуют RPC: проверяются события и продолжение индексации, математические
границы Uniswap, проценты Aave, единый блок, сбои синхронизации, бэкапы,
авторизация, запись на диск и конкурентные изменения журнала.

Модули: `fund` — текущие данные контрактов; `portfolio` — размещение капитала;
`snapshot` — публичный снимок; `sync` — обновление и фиксация блока; `storage` —
файлы и журнал владельца; `auth` — проверка ключа; `http` — API; `config` —
параметры запуска. Команды обслуживания находятся в `cli`.
