# Free Mine Public Server

Публичный сервер Free Mine для Avalanche C-Chain (`43114`). Агрегирует текущее
состояние контрактов и портфеля `OreVein`, отдаёт публичный бэкап и хранит
записи транзакций владельца. Доменная модель — в
[free-mine/contracts](https://github.com/free-mine/contracts).

## Запуск

Скопируйте `.env.example` в `.env` и задайте переменную:

```dotenv
RPC_URL=https://адрес-вашего-rpc
```

`RPC_URL` обязателен. Нужен HTTP(S) RPC Avalanche с доступом к событиям
с момента деплоя и состоянию выбранного блока. Первичная индексация может
занять время; после неё сервер читает только новые блоки.
При ограничении диапазона `eth_getLogs` сервер уменьшает размер запроса и
использует его до конца обновления. RPC с лимитом в 10 блоков потребует
сотни тысяч запросов для загрузки многомиллионной истории; для первого
запуска восстановите доверенный бэкап либо выберите RPC с большим диапазоном
и увеличьте `logBatchSize` в `src/config/constants.ts`.

```sh
docker compose up -d
```

Сервер доступен на порту `3000`. Порт хоста меняется в
`compose.yml`. Адреса контрактов, токены, пары, интервал обновления в 10 минут
и остальные настройки находятся в `src/config/constants.ts`.
После изменения кода: `docker compose up -d --build`.

Один контейнер, без СУБД и именованных Docker volumes. Единственное
подключение `./data:/app/data` сохраняет файлы рядом с проектом:

- `data/public-snapshot.json.gz` — публичное состояние и последний блок.
- `data/transactions.json` — записи владельца.
- `data/owner-key.sha256` — хеш ключа владельца.

Эта папка сохраняется при пересоздании контейнера. Один каталог данных
должен использовать только один запущенный экземпляр сервера.

## Ключ владельца

После запуска создайте ключ:

```sh
docker compose exec server node dist/cli/key.js
```

Команда выводит секретный ключ и записывает его SHA-256 в
`data/owner-key.sha256`. Сохраните ключ на локальном сервере владельца и
передавайте его в `Authorization: Bearer <ключ>` через HTTPS.

Для смены ключа повторите команду или замените файл хеша вручную:
64 шестнадцатеричных символа SHA-256. Сервер читает файл при каждом запросе,
перезапуск не нужен. Без корректного хеша запросы владельца возвращают `401`;
публичное чтение не требует ключа.

## Публичные данные

Сервер обновляет состояние сразу при запуске, затем через 10 минут после
завершения успешного обновления и по запросу владельца. После ошибки фоновая
попытка повторяется через минуту. Все данные снимка относятся к одному блоку;
его номер, хеш и время передаются вместе с данными. Ошибка RPC оставляет
предыдущий снимок доступным.
До завершения первой синхронизации запросы состояния и бэкапа возвращают `503`.
Одновременные запросы обновления используют одну синхронизацию.
Если `GET /v1/status` показывает `running: false` и непустой `lastError`,
обновление завершилось ошибкой. Поле `lastError` и логи контейнера указывают
этап сбоя без раскрытия RPC URL. После устранения причины перезапустите
контейнер или вызовите `POST /v1/refresh`, чтобы запустить обновление сразу.

Размер запроса событий по умолчанию — 10 блоков, совместимый с Alchemy Free.
При запуске сервер загружает `data/public-snapshot.json.gz`, проверяет хеш
сохранённого блока и последовательно читает все пропущенные блоки после него
до блока, выбранного в начале обновления. Простой сервера не приводит к
пропуску событий. Промежуточные результаты не публикуются: при ошибке или
прерывании остаётся последний целый снимок, и следующая попытка продолжится
от него. Сохраняйте каталог `data` между запусками; без снимка история читается
заново с деплоя, что на Alchemy Free может занять много времени.

История не сохраняется. Публичны:

- Держатели и балансы `MagicOre`.
- Владелец, администраторы и расписание преемников `OreVein`.
- Цена входа, долларовый токен, активные заявки и необходимые смены `FreeMine`.
- Балансы AVAX, WAVAX, BTC.b, USDT и USDC на `OreVein`.
- Вклады WAVAX/BTC.b и долги USDT/USDC в Aave с начисленными процентами,
  а также Health Factor (`null`, если долга нет).
- NFT-позиции `OreVein` в Uniswap V3: WAVAX/USDC и BTC.b/USDC, комиссия 0,05%.
  Для каждой позиции — оба актива, диапазон и текущая цена в USDC, суммы к получению.

Преемник получает право вызвать `claimPrivileges` с указанного времени;
автоматического получения полномочий нет. Заблокированные в заявках токены
находятся на балансе `FreeMine`; связь с пользователем находится в `claims`.
Из смен сохраняются текущая, предыдущая и более ранние с активными заявками.

Суммы и идентификаторы контрактов передаются десятичными строками.
Суммы — в минимальных единицах токена, `decimals` указано в его описании.
Цена входа `FreeMine` имеет 18 знаков. Цены и границы Uniswap — обычные
десятичные строки цены базового актива в USDC; `fullRange` обозначает полный
диапазон. Расчёты используют `bigint`.

Поля позиции Uniswap (`base` и `quote` обозначают оба актива):

| Поле | Содержимое |
| --- | --- |
| `amounts` | Активы в действующей ликвидности |
| `newlyAccruedFees` | Комиссии после последнего обновления учёта позиции |
| `storedOwed` | Суммы, уже записанные контрактом к получению |
| `totalCollectable` | `storedOwed + newlyAccruedFees` |

Uniswap объединяет ранее учтённые комиссии и выведенный, но ещё не полученный
капитал в `tokensOwed`. Поэтому `storedOwed` и `totalCollectable` могут включать
оба; разделить их только по текущему состоянию нельзя. Если `storedOwed = 0`,
`newlyAccruedFees` содержит все комиссии к получению.

Чтобы добавить токен или пару, измените `tokens` или `pairs` в
`src/config/constants.ts` и пересоберите образ. Роль токена в Aave задаётся
полем `aave: 'supply' | 'borrow'`; поле необязательно. Пара ссылается на символы
токенов, `fee: 500` соответствует 0,05%.

## API

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| `GET /v1/status` | публичный | Ход обновления, блок и время снимка, последняя ошибка |
| `GET /v1/state` | публичный | `{format, chain, block, updatedAt, fund, portfolio}` |
| `GET /v1/backup` | публичный | Сжатый снимок `free-mine-backup.json.gz` |
| `POST /v1/refresh` | владелец | `202`: обновление запущено или уже выполняется |
| `GET /v1/transactions` | владелец | `{records: [...]}` |
| `GET /v1/transactions/:id` | владелец | Запись и `ETag` с ревизией |
| `PUT /v1/transactions/:id` | владелец | Создание или полная замена JSON-объекта |
| `DELETE /v1/transactions/:id` | владелец | Удаление записи, `204` |

Публичное чтение доступно браузерам через CORS. Хранилище транзакций принимает
JSON-объекты клиента; сервер не подписывает, не отправляет и не проверяет
транзакции. Максимальное тело запроса — 1 MiB. ID: 1–128 символов из букв ASCII,
цифр и `._:-`, первый символ — буква или цифра.

Для создания передайте `If-None-Match: *`:

```http
PUT /v1/transactions/operation-123
Authorization: Bearer <ключ>
If-None-Match: *
Content-Type: application/json

{"hash":"0x...","status":"submitted"}
```

Ответ содержит `{id, revision, updatedAt, data}` и `ETag`, например `"1"`.
Для изменения или удаления передайте эту ревизию в `If-Match: "1"`.
Без условия — `428`, при конфликте — `412`; прочитайте актуальную запись
перед повторной попыткой. Это защищает журнал от перезаписи устаревшим клиентом.
Ответ об успехе возвращается после сохранения на диск.

## Бэкап

```sh
curl --fail http://localhost:3000/v1/backup --output backup.json.gz
```

Для восстановления поместите доверенный бэкап в
`data/public-snapshot.json.gz` перед запуском сервера. На существующем сервере
сначала выполните `docker compose stop`, сохраните прежний снимок, затем
замените файл и выполните `docker compose up -d`.

При запуске сервер проверяет формат, сеть, адреса и согласованность данных.
Обновление продолжается после сохранённого блока с проверкой его хеша в RPC.
Публичный бэкап не содержит журнал транзакций и хеш ключа.

При переходе с прежней конфигурации скопируйте два файла данных из старого
именованного volume в `./data`, а `secrets/owner-key.sha256` — в
`data/owner-key.sha256` до пересоздания контейнера. Старый volume автоматически
не удаляется.

## Разработка

Требуется Node.js 24. `npm ci`, затем `npm run dev` для запуска с `.env`.
`npm run key:generate` создаёт ключ локально. `npm run check` проверяет типы,
ESLint, OpenAPI, форматирование документации и workflows, тесты и сборку.
Тесты работают без RPC. Отдельная проверка документации: `npm run docs:lint`.

## Swagger и GitHub Actions

Техническая документация API находится в [`swagger/openapi.yml`](swagger/openapi.yml).
[`swagger/index.html`](swagger/index.html) отображает её в Swagger UI: эндпоинты,
схемы данных, примеры, авторизация, ошибки и правила работы с ревизиями.
При изменении HTTP API обновляйте спецификацию в том же Pull Request.

Для локального просмотра раздайте каталог `swagger` любым статическим HTTP-сервером,
например `python -m http.server 8080 --directory swagger`, и откройте
`http://localhost:8080`. Открытие HTML через `file://` не позволяет загрузить YAML.
CSS и JavaScript Swagger UI загружаются с CDN; версия закреплена, файлы проверяются
браузером по integrity-хешам.

В Swagger UI выберите сервер и используйте **Try it out** для запросов.
Для удалённого сервера укажите его HTTPS-адрес; GitHub Pages размещает только
документацию. Для запросов владельца в **Authorize** введите ключ без префикса
`Bearer`. Ключ не сохраняется между перезагрузками страницы.

Для публикации один раз выберите в репозитории **Settings → Pages → Build and
deployment → Source → GitHub Actions**. Workflow `Swagger Pages` публикует
каталог `swagger` после успешных проверок при каждом push в `main`.
Его также можно запустить вручную для `main` через **Actions → Swagger Pages →
Run workflow**. Ожидаемый адрес: <https://free-mine.github.io/server/>;
точный URL появляется в deployment окружения `github-pages`.
Дополнительные секреты для публикации не нужны.

Workflow `CI` проверяет Pull Requests: установка через `npm ci`, типы TypeScript,
ESLint без предупреждений, валидность OpenAPI, форматирование документации и
workflows, тесты, сборка TypeScript и Docker. Эти же проверки обязательны для
workflow публикации. RPC и ключ владельца для CI не требуются.
GitHub Actions закреплены по SHA релизов с Node.js 24; Dependabot еженедельно
предлагает их обновления.
