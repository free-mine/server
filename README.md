# Free Mine Public Server

Сервер обеспечивает работу:
1. Клиентского веб-приложения Free Mine;
2. Локального сервера владельца системы.

Доменная модель описана в репозитории https://github.com/free-mine/contracts.

## Функциональность

Смарт-контракты публикуют события в ходе своей работы. Сервер должен агрегировать эти события в текущее состояние, хранить его вместе с номер блока, для которого это состояние актуально и отдавать данные по запросу.

Периодически (например, каждый час) сервер запрашивает RPC-провайдер, обновляя текущее состояние и номер актуального блока.

Для локального сервера владельца системы публичный сервер служит надёжным хранилищем данных о текущем состоянии транзакций.

## Данные

Во-первых, агрегируются данные самих контрактов из системы Free Mine:
- Адреса и количество `MagicOre` держателей.
- Расписание вступления в должность преемников `OreVein`.
- Цены, заявки и прочие данные `FreeMine`.

Во-вторых, агрегируются данные размещения капитала на адресе `OreVein`. Наблюдаемые токены: WAVAX, BTC.b, USDT и USDC. Также, WAVAX и BTC.b в качестве вкладов в AAVE, а USDT и USDC в качестве долга в AAVE. Должно быть понятно, сколько чего вложено и сколько чего взято (без долларовых эквивалентов). Если из AAVE можно запросить Health Factor, то и его тоже.

Также в размещение капитала входят торговые пары в Uniswap V3 (с полным или ограниченным диапазоном):
- WAVAX/USDC 0.05%.
- BTC.b/USDC 0.05%.
Должно быть понятно, какие торговые пары созданы и какой в них диапазон. Диапазон должен быть не в виде тиков, а в виде стоимости волатильного актива в USDC. Также надо агрегировать и текущую стоимость волатильного актива в USDC для каждой торговой пары.

Код должен быть написан таким образом, чтобы не было проблемой добавить поддерживаемые токены и торговые пары.

## Авторизация

Локальный сервер владельца системы отправляет секретный ключ при каждом запросе. Хеш этого ключа должен совпадать со значением, которое публичный сервер хранит локально в отдельном файле (чтобы я мог менять секретный ключ, просто обновив файл).

## Бэкапы

При агрегации данные контрактов из системы Free Mine вместе с номером последнего актуального блока должны сохраняться в файл. Желательно в оптимизированном виде. Этот файл доступен для скачивания кому угодно, потому что ничего секретного в нём нет, только данные из блокчейна. Я буду периодически скачивать этот файл в качестве бэкапа, чтобы при переустановке сервера не приходилось перебирать все блоки заново.

Соответственно, новый сервер должен иметь механизм чтения файла-бэкапа и применения данных из него.

## Технологии

Код сервера должен быть написан на TypeScript, а сам сервер должен запускаться командой `docker compose up -d`, то есть содержать в корне `compose.yml`, в котором будут описаны все зависимости сервера (например, СУБД, если нужна). Если зависимости не нужны серверу, то и хорошо, будет `compose.yml` с одним сервисом. Для RPC-провайдера используй EthersJs.

ESLint + Prettier должны быть настроены по предоставленной конфигурации.
